Fun with Flow Models

Part A pushes a pretrained text-to-image flow model through denoising, editing and optical illusions. Part B trains flow matching from scratch on MNIST.

Overview A1 · Training & sampling A2 · Guidance A3 · Creative B1 · Denoiser B2 · Flow matching Takeaways

00Overview

Forward path

xt = (1 − t) x0 + t x1,  x0 = ε ∼ 𝒩(0, I)

Training target — the velocity of that straight path

v = dxt/dt = x1 − x0

The network is trained to predict that velocity from (xt, t, c), and sampling just follows the predicted velocity from noise to data with Euler steps.

Part A · pretrained PixNerd

A1Visualizing Training and Sampling

For Sections 1.1–1.5, I used one photo of my own throughout: a rocky outcrop at Point Lobos, with a sharp central peak, layered boulders, a clean horizon and some white water on the right. The provided preprocessing center-crops it to 512×512 and maps RGB to [−1, 1].

1.1  Constructing noisy training inputs

The forward process: as t goes down, the image is scaled down while the noise is scaled up. I sampled one noise tensor (seed 180) and reused it at t = 0.25, 0.50 and 0.75, so the only thing changing across the row is t. Both endpoints are checked with torch.equal (t = 0 gives exactly the noise, t = 1 gives exactly the image).

show code · interpolate
def interpolate(image, noise, t):
    """x_t = (1 - t) * noise + t * image"""
    if not 0.0 <= t <= 1.0:
        raise ValueError(f"t must be in [0, 1], got {t}")
    return (1.0 - t) * noise + t * image

# endpoint checks (exact, because multiplying by 0.0 / 1.0 is exact in float)
assert torch.equal(interpolate(image, epsilon, 0), epsilon)
assert torch.equal(interpolate(image, epsilon, 1), image)

t = 0.25. Almost nothing. It’s high-contrast, multicolored grain, with a faint dark blob where the peak sits and a darker mass lower down. Color is gone completely (the dominant colors are just the random RGB noise).

t = 0.50. The coarse shapes are back: the triangular peak, the big boulders, and the horizon separating sky from sea. The sky is lighter than the rocks again. The grain still eats the finer stuff, so the cracks on the rock face and all the sea texture are gone.

t = 0.75. It’s nearly the photo. The muted gray-blue water and warm tan rock are back, and you can see the layered cracks and dark crevices under a light grain.

What’s invisible at 0.25 but clear at 0.75? The horizon line. At t = 0.25, the noise has weight 0.75 and the image only 0.25, so the top of the frame is just more noise. At 0.75, the weights flip and there’s an obvious edge where pale sky meets dark water. Big smooth structures (the peak, the horizon, overall brightness) come back first because they cover so many pixels that their signal survives heavy noise. Fine texture is only a few pixels wide, so it’s the last thing to return.

1.2  Classical denoising

Baseline with no learned model: divide by t to restore the image’s amplitude, then Gaussian-blur. Dividing doesn’t remove any noise, it just fixes the scale: xt/t = x1 + ((1 − t)/t) ε. I swept σ = 1, 2, 4, 8, 16 and kept whichever had the lowest MSE against the clean image, which gave σ = 8, 4 and 1 for t = 0.25, 0.50 and 0.75.

What blur does well: It kills most of the grain, and at t = 0.50 and 0.75, you get a clean, readable scene. What it costs: It averages real detail along with the noise. At t = 0.50, the rocks turn into soft blobs. At t = 0.25, you get a colour-blotched smear with a dark central mass.

Why t = 0.25 is so much worse: The image lives in [−1, 1], so noise with std 3 is three times bigger than the signal. A Gaussian blur only cuts independent per-pixel noise by about 0.28/σ, so you’d need a huge σ, and a huge σ erases the picture along with the noise. Small σ leaves the noise, large σ removes the image.

1.3  One-step denoising

Now the pretrained model. predict_velocity(x, t, c) gives a velocity, so I jump all the way to the clean end of the path in one go (the prompt is "a high quality photo"):

x1 = xt + (1 − t) vθ(xt, t, c)A.2

Before using it I checked that the velocity has the same shape, dtype and device as the input, and that it’s finite.

show code · one_step_denoise
def one_step_denoise(x, t, condition, predict_velocity):
    """x1_hat = x_t + (1 - t) * v_theta(x_t, t, c)"""
    v = predict_velocity(x, t, condition)
    return x + (1.0 - t) * v

t = 0.25. A clean, noise-free scene with the sea, horizon and rock outcrop in the right places. It’s heavily smoothed though: soft rocks, no cracks. t = 0.50. Much sharper than the blur at the same t. The peak, boulders and horizon line up, and there’s some shading and texture, but the fine cracks and sea texture are softened and the colors are a bit washed out. t = 0.75. Almost identical to the original, and far cleaner than the blur, which still had visible grain. Only the finest rock texture and the sea are slightly smoothed.

It gets steadily better as t grows, and the reason is that a single step can only give you the average clean image that could have produced this input, E[x1 | xt]. At t = 0.25, the input is consistent with a huge set of images, so that average is smooth and generic. As t grows, the noisy image pins the answer down, the set of possibilities shrinks, and the average sharpens.

1.4  Visualizing velocity

The error map is the per-pixel RMS difference of the two updates across RGB, computed before any display scaling. Both updates share one symmetric RGB scale with zero at middle gray, and the error maps share one limit across all three times.

show code · velocity_diagnostics
@torch.inference_mode()
def velocity_diagnostics(x_t, t, clean_image, epsilon, condition, predict_velocity):
    v_hat = predict_velocity(x_t, t, condition)
    v_gt = clean_image - epsilon
    predicted_update = (1.0 - t) * v_hat
    ground_truth_update = (1.0 - t) * v_gt          # = x_1 - x_t
    # average ONLY over the RGB axis so every pixel keeps its own error value
    error_map = ((predicted_update - ground_truth_update) ** 2).mean(dim=1).sqrt()
    return predicted_update, ground_truth_update, error_map

Where is the error biggest? At edges and fine texture. At t = 0.25, the brightest error pixels trace the rock outline, the peak edge and the cracks on the boulders, with a bit along the shoreline. The sky and smooth sea stay dark. The predicted update is a smooth, low-frequency version of the ground truth: it gets the big shapes and the light/dark pattern roughly right but misses the sharp crack detail.

How does it change from 0.25 to 0.75? It shrinks a lot. By 0.75, nearly the whole error map is dark, with faint speckle on the rock. Two things are going on: both updates get multiplied by (1 − t), so the update itself drops from 0.75 of the velocity at t = 0.25 to 0.25 at t = 0.75; and the noisy input already contains most of the image by then, so the model’s velocity prediction is better to begin with. The update images show the same thing, with structure at 0.25 and almost flat gray by 0.75.

Is the predicted update believable? Yes. The rock sits in the same place, light and dark regions go the same way, and sky and sea are roughly neutral. It’s just much smoother than the truth, which fits what we saw in 1.3: the model predicts a plausible average direction, not the exact one.

1.5  Iterative denoising with Euler sampling

One-step denoising is inaccurate because the velocity changes as you move along the path. So instead I take a small step, ask the model again, and repeat:

xt+h = xt + h vθ(xt, t, c)A.3

A few details in euler_sample: the number of steps is fixed up front as ceil((1 − t_start)/h − 1e-9) (the 1e-9 stops 0.5/0.02 = 25.000000000000004 from becoming 26 steps), each time is computed from the step index so float error doesn’t pile up, and the last step is shortened so it lands on exactly t = 1 without ever calling the model past 1.

show code · euler_sample
@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity, save_every=5):
    """Integrate dx/dt = velocity(x, t) from t_start to exactly t = 1."""
    x = x_start.float()
    # the 1e-9 stops 0.5/0.02 = 25.000000000000004 from becoming 26 steps
    n_steps = math.ceil((1.0 - t_start) / step_size - 1e-9)
    states = [(float(t_start), x)]

    for i in range(n_steps):
        t = t_start + i * step_size          # from the index, so float error never accumulates
        h = min(step_size, 1.0 - t)          # last step is shortened to land on 1
        x = x + h * velocity(x, t)           # velocity is recomputed every step
        last = i == n_steps - 1
        t_next = 1.0 if last else t + h
        if last or (save_every and (i + 1) % save_every == 0):
            states.append((t_next, x))
    return x, states

Layout first, detail last. At t = 0.50, you can only see the peak, the big boulders and the horizon, under heavy grain. By 0.60–0.70, the rock forms firm up and the main cracks start to show while sky and sea are still noisy. At 0.80, the scene is clear but the sky is still grainy, and the last stretch to 1.00 clears the remaining noise and sharpens the sea ripples and rock cracks. Each step only has to settle a small amount of uncertainty, and it’s consistent with the layout the earlier steps already committed to.

Which is closest? Euler. Its cracks, crevices, sea texture and the white water on the right line up with the real photo, and the leftover differences are small (slightly cooler colors). The blur is a smeared, colour-blotched version that keeps only a rough silhouette. The one-step estimate is clean and plausible but looks soft and painted.

1.6  Generating images from noise

The same euler_sample can generate from scratch: start at t = 0 from pure Gaussian noise and integrate all the way to 1 (50 steps), with "a high quality photo". Five independent noises, seeds 180–184.

Every single sample is a portrait of a person, even though the prompt never mentions people. With no subject given, the model falls back on what its training data most associates with “high quality photo”, which is a posed, studio-style portrait: one person in the middle, plain or soft background, muted colors. Quality is uneven too. Only 182 and 184 are properly convincing. The problems cluster in what humans are most sensitive to (faces, hands, skin and body texture). This is the weakness classifier-free guidance is supposed to fix.

A2Conditional Generation and Guidance

2.1  Classifier-free guidance

For each step, I evaluate the model twice at the same xt and t, once with the prompt and once with the empty-string embedding, and push the prediction away from the unconditional one:

vcfg = vc + w (vc − vu)A.4

w = 7 and h = 0.02. With w = 0 it has to reproduce the plain conditional prediction, which I assert with torch.equal.

show code · cfg_velocity
def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    """v_cfg = v_c + w * (v_c - v_u)"""
    v_c = predict_velocity(x, t, condition)
    v_u = predict_velocity(x, t, null_condition)
    return v_c + w * (v_c - v_u)

All five now look like polished professional photographs. Faces are symmetric and properly formed, eyes are sharp, skin has believable texture, and none of the 1.6 artifacts survive. The remaining flaw is a slightly over-smooth, airbrushed look. The composition mostly carries over from the noise (you can still see the hand at the cheek in 182), so guidance changes quality more than layout.

What happened to diversity? It dropped a lot. In 1.6, the samples varied in framing, pose, lighting, palette and quality. Now they’re all centered, front-facing head-and-shoulders portraits with studio lighting, a plain backdrop and a faint smile; only identity details differ (hair, skin tone, clothing, backdrop brightness). This is the CFG trade-off: it pushes every sample along “what makes this a high-quality photo”, which raises quality and consistency and drags everything toward the same prototype portrait. It also doesn’t fix the underlying bias: the generic prompt still means “person”, just a more polished one.

A3Creative Applications

3.1  Image-to-image editing

This is SDEdit. Noise a real image up to tstart with interpolate, then run the guided Euler sampler from there to t = 1 with "a high quality photo". The model has to hallucinate to clean the image up, which projects it back onto the manifold of natural images. A small start time means a lot of noise (a big edit); a big start time keeps most of the input. Every sweep uses the same seven times, and each figure shows the original first, then tstart ∈ {0.02, 0.04, 0.06, 0.10, 0.14, 0.25, 0.50}.

show code · edit
def edit(image, noise, t_start, condition, predict_velocity, w=7, step_size=0.02):
    x_t = interpolate(image, noise, t_start)           # noise the image up to t_start

    def velocity(x, t):
        return cfg_velocity(x, t, condition, w, predict_velocity)

    x, _ = euler_sample(x_t, t_start, step_size, velocity, save_every=0)
    return x

Campanile and two of my own photos

One web image and two hand-drawn sketches

What changes most at small start times? At 0.02 and 0.04, basically nothing survives except global colour and layout, and the model invents something new from its own prior and then reads whatever it can from what’s left. The cat becomes a studio portrait of a person (the same portrait bias from 1.6 and 2.1), Remy becomes a man or a hand against a blue wall, and the Campanile becomes a plain pillar. The two sketches change the most: they’re mostly flat white with a few black lines, so almost no signal survives, and the model sees blank white space and makes a white product-style object (a phone, a sheet of paper, a smooth shape). The garbled text on the minion is the model hallucinating.

Photos vs. cartoon vs. drawings. The photos need a start time of about 0.25 before the original really returns. The cartoon returns earlier (about 0.10), and the drawings earliest (0.06), because a bold black outline or a big saturated shape on a flat background is exactly the kind of high-contrast, low-frequency structure that survives noise. The photos have lots of mid-contrast texture, which noise buries first.

3.3  Visual anagrams

A visual anagram is one image that reads as one thing upright and another when you turn it 180°. At each step the upright image is denoised with prompt A, a rotated copy is denoised with prompt B, B’s velocity is rotated back so it lines up with the original pixels, and the two are averaged:

v = ½ [ vcfg(xt, t, pa) + F( vcfg(F(xt), t, pb) ) ]A.5

F is a 180° rotation, which flips both spatial axes (not just vertical reflection), so it’s its own inverse; I assert rotate180(rotate180(x)) == x.

show code · visual_anagrams
def rotate180(x):                       # provided: flips BOTH spatial axes
    return torch.flip(x, (-2, -1))

def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def velocity(x, t):
        v_a = cfg_velocity(x, t, condition_a, w, predict_velocity)
        v_b = rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity))
        return 0.5 * (v_a + v_b)

    x, _ = euler_sample(noise, 0.0, step_size, velocity, save_every=0)
    return x

Do both read equally well? Not quite. In the castle / ship one, the ship is the clearer one when rotated: hull, stacked sails, wake and choppy waves are all there. The castle is weaker. There are towers, a walled fortress and a cliff at the top, but the cliff face is made of sail-like fragments, so it’s more ambiguous. The thing that makes this pair work is that sails and cliff share the same vertical, striped shapes. In the vase / woman one, the vase is stronger: upright it’s a clear bouquet with a rounded base. Rotated, a face with hair shows up at the top and the flowers become a bodice, but the face is faint and blurry and the figure is mostly flowers.

Pairs that didn’t work. Before these I tried “a watercolor painting of a majestic owl perched on a branch” with “a watercolor painting of a calm pine forest reflected on a clear lake” (the owl dominated), and “a vintage botanical illustration of a blooming sunflower” with “a vintage illustration of a hot air balloon floating above clouds” (the balloon dominated).

My read on why: layout is decided at low frequency early in sampling, and whichever view locks onto a confident layout first (the owl’s face and eyes, the balloon’s round envelope) drags the shared image toward it, so the other prompt has to fit around it. When the two layouts can’t share the same pixels under a 180° turn, the averaged velocity can’t satisfy both and the stronger one wins. The pairs that worked share some structure: sails and cliffs are both vertical stripes, and flowers can be a bouquet or a dress.

3.4  Hybrid images

Same idea as the hybrid images in Project 2, but done on the velocity field (Factorized Diffusion). I get a CFG velocity for each of two prompts at the same xt and t, and take the low frequencies from one and the high frequencies from the other:

v = lowpass(va) + vb − lowpass(vb)A.6

The low-pass is a Gaussian blur with kernel 265 and σ = 16 at 512×512. Prompt a · low sets what you see from far away and prompt b · high sets what you see up close. Each hybrid is shown below at full size with a slider that moves it “farther away” (shrinks it), plus the real 64×64 version.

show code · lowpass + make_hybrids
def lowpass(x, sigma=16.0):             # provided: kernel 265, sigma 16 at 512 x 512
    kernel = 2 * round(16.5 * x.shape[-1] / 64) + 1
    return gaussian_blur(x, [kernel, kernel], [sigma, sigma])

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    """a = distant (low-frequency) prompt, b = close-up (high-frequency) prompt"""
    def velocity(x, t):
        v_a = cfg_velocity(x, t, condition_a, w, predict_velocity)
        v_b = cfg_velocity(x, t, condition_b, w, predict_velocity)
        return lowpass(v_a) + v_b - lowpass(v_b)

    x, _ = euler_sample(noise, 0.0, step_size, velocity, save_every=0)
    return x

Failed attempts. Distant “a lithograph of a lion’s head” with close “a lithograph of a desert dunes landscape”: I couldn’t make out either, and it looked more like an isopod. Distant “a pencil sketch of a tree” with close “a pencil sketch of a flock of birds”: only the birds showed up. A lion’s head has a complicated silhouette and the dunes’ repeating ripples are high-contrast detail that overwhelmed it. A pencil-sketch tree is mostly thin low-contrast lines, too faint to survive in the low-frequency band, while the flock is made of many sharp little shapes that dominate.

Part A, in one paragraph

The thing that tied all of Part A together for me is that the model decides layout first and detail last. You can see it in the Euler trajectory (peak and horizon before cracks), in why one-step denoising gives a smooth average, in why SDEdit needs a start time of about 0.25 before photos come back, and in why anagrams and hybrids only work when the two prompts can agree on coarse structure. Guidance buys you quality at the cost of variety and doesn’t fix the model’s idea of what a “high quality photo” is, which is a portrait.

Part B · flow matching from scratch

B1Single-Step Denoising UNet

Everything in Part B uses MNIST with pixels in [0, 1], trained on the 60,000 training images only (shuffled), with the test set held out for visualization.

1.1  Implementing the UNet

The denoiser is a UNet built from a small set of ops, each followed by BatchNorm and GELU (except Flatten, which is pool then GELU): Conv (3×3, stride 1, changes channels only), DownConv (3×3, stride 2, halves H and W), UpConv (4×4 transposed, stride 2, doubles H and W), Flatten (7×7 average pool, 7×7 → 1×1), and Unflatten (7×7 transposed conv with stride 7, 1×1 → 7×7). On top of those, ConvBlock, DownBlock and UpBlock pair a resampling op with an extra Conv so the network gets deeper without changing any shapes.

Shapes through the encoder, bottleneck and decoder

1×28×28 → D×28×28 → D×14×14 → 2D×7×7 → 2D×1×1 → 2D×7×7 → D×14×14 → D×28×28 → 1×28×28

Skip connections concatenate each decoder input with the encoder feature at the same resolution, which is why the decoder blocks take 4D, 2D and 2D input channels. There’s no activation on the final conv, since the output is unbounded. With D = 128 it has about 7.89M parameters, and every shape matches the quick checks in the notebook.

show code · the basic ops
class Conv(nn.Module):          # Conv2d(3, s=1, p=1) -> BN -> GELU, keeps H and W
    def __init__(self, in_channels, out_channels):
        super().__init__()
        self.net = nn.Sequential(nn.Conv2d(in_channels, out_channels, 3, 1, 1),
                                 nn.BatchNorm2d(out_channels), nn.GELU())
    def forward(self, x): return self.net(x)

class DownConv(nn.Module):      # Conv2d(3, s=2, p=1) -> BN -> GELU, halves H and W
    def __init__(self, in_channels, out_channels):
        super().__init__()
        self.net = nn.Sequential(nn.Conv2d(in_channels, out_channels, 3, 2, 1),
                                 nn.BatchNorm2d(out_channels), nn.GELU())
    def forward(self, x): return self.net(x)

class UpConv(nn.Module):        # ConvTranspose2d(4, s=2, p=1) -> BN -> GELU, doubles H and W
    def __init__(self, in_channels, out_channels):
        super().__init__()
        self.net = nn.Sequential(nn.ConvTranspose2d(in_channels, out_channels, 4, 2, 1),
                                 nn.BatchNorm2d(out_channels), nn.GELU())
    def forward(self, x): return self.net(x)

class Flatten(nn.Module):       # AvgPool2d(7) -> GELU, (N,C,7,7) -> (N,C,1,1)
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(nn.AvgPool2d(kernel_size=7), nn.GELU())
    def forward(self, x): return self.net(x)

class Unflatten(nn.Module):     # ConvTranspose2d(7, s=7) -> BN -> GELU, (N,C,1,1) -> (N,C,7,7)
    def __init__(self, in_channels):
        super().__init__()
        self.net = nn.Sequential(nn.ConvTranspose2d(in_channels, in_channels, 7, 7, 0),
                                 nn.BatchNorm2d(in_channels), nn.GELU())
    def forward(self, x): return self.net(x)

# composed ops: same H, W, channels as their parts, just deeper
ConvBlock = Conv(in, out) -> Conv(out, out)
DownBlock = DownConv(in, out) -> ConvBlock(out, out)
UpBlock   = UpConv(in, out)   -> ConvBlock(out, out)
show code · the UNet body
class _UNetBody(nn.Module):
    def __init__(self, in_channels, num_hiddens):
        super().__init__()
        D = num_hiddens
        self.conv_in   = ConvBlock(in_channels, D)   # (N, D, 28, 28)
        self.down1     = DownBlock(D, D)             # (N, D, 14, 14)
        self.down2     = DownBlock(D, 2 * D)         # (N, 2D, 7, 7)
        self.flatten   = Flatten()                   # (N, 2D, 1, 1)
        self.unflatten = Unflatten(2 * D)            # (N, 2D, 7, 7)
        self.up1       = UpBlock(4 * D, D)           # cat(2D, 2D) -> (N, D, 14, 14)
        self.up2       = UpBlock(2 * D, D)           # cat(D, D)   -> (N, D, 28, 28)
        self.conv_out  = ConvBlock(2 * D, D)         # cat(D, D)   -> (N, D, 28, 28)
        self.head      = nn.Conv2d(D, in_channels, 3, 1, 1)

    def _forward(self, x, modulate1=None, modulate2=None):
        x0 = self.conv_in(x)
        d1 = self.down1(x0)
        d2 = self.down2(d1)
        unflatten = self.unflatten(self.flatten(d2))
        if modulate1 is not None: unflatten = modulate1(unflatten)   # conditioning hook 1
        up1 = self.up1(torch.cat([d2, unflatten], dim=1))
        if modulate2 is not None: up1 = modulate2(up1)               # conditioning hook 2
        up2 = self.up2(torch.cat([d1, up1], dim=1))
        out = self.conv_out(torch.cat([x0, up2], dim=1))
        return self.head(out)                                        # no activation

1.2  Using the UNet to train a denoiser

The task: given a noisy z, output the clean x, minimizing ‖Dθ(z) − x‖², where the training pairs come from z = x + σ ε, ε ∼ 𝒩(0, I). Here’s that noising process on four test digits with the same ε at every σ, so the only thing changing along a row is σ:

show code · noising and the training step
def add_noise(x, sigma, eps=None):
    """z = x + sigma * eps,  eps ~ N(0, I)"""
    if eps is None:
        eps = torch.randn_like(x)
    return x + sigma * eps

# training step: fresh noise every batch, so every epoch sees new (z, x) pairs
z = add_noise(images, noise_level)          # sigma = 0.5
loss = F.mse_loss(model(z), images)         # ||D(z) - x||^2

At σ = 0.5, you can still tell what the digit is, but by σ = 1.0, the noise has the same std as the entire pixel range and the stroke is barely there.

1.2.1  Training at σ = 0.5

D = 128 · batch 256 · Adam, lr 1e-4 · 5 epochs · σ = 0.5 · fresh noise every batch

I draw a new ε every time a batch is fetched, so each epoch sees the same digits with different noise. The loss falls off a cliff in the first few hundred iterations and then grinds down slowly. After 5 epochs, the held-out test MSE at σ = 0.5 is 0.0083.

After one epoch, the digits are already readable but soft and a little blotchy. By epoch 5, the strokes are crisper and the background is basically clean.

1.2.2  Out-of-distribution noise

The model has only ever seen σ = 0.5, so I ran it on the same two digits across the whole range of σ.

For σ ≤ 0.5, it does fine, including σ = 0, where it just has to pass the digit through. Above 0.5, it starts keeping blobs of the noise as bits of stroke (the 2 grows a stray tail at 0.6), and at σ = 0.8 and 1.0, the digit is partly hallucinated: the 7 turns into a scribbly loop and the 2 into a tangle. My explanation is that the network has only ever seen one noise level, so it has learned roughly how much to subtract for σ = 0.5. When there’s more noise than that, it under-corrects.

1.2.3  Denoising pure noise

To make denoising generative, I retrained a fresh D = 128 UNet the same way (5 epochs, lr 1e-4, batch 256) but with the input replaced by pure noise z = ε. The target is still a clean digit, so now the input carries no information about which digit it’s paired with.

What comes out: Pretty much the same image every time, whatever noise I feed in. It’s a fuzzy, symmetric-ish blob that looks like every digit stacked on top of each other: a bright ring that could be a 0, with a smear down the middle where the 1s, 7s and 4s overlap. It doesn’t look like any one class. Across 256 different noise inputs, the average per-pixel std of the outputs is just 0.0068, and the average output is almost exactly the plain pixelwise average of the training set.

Why. Under MSE, the best prediction is the conditional mean, E[x | z]. Since ε is independent of x, that’s just E[x], the centroid of the whole dataset. So the network learns to ignore its input and output the average digit, and the loss plateaus around 0.067, which is the irreducible leftover variance of the digits around their mean. This is why one-step denoising can’t be a generative model: with zero information it collapses to the global mean. Iterative denoising gets around it by taking many small steps, where each one only has to resolve a little uncertainty.

B2Flow Matching

One-step denoising can’t generate, so now the UNet predicts the flow instead. For a clean digit x1, noise x0 ∼ 𝒩(0, I) and t ∼ U[0, 1] the model sees xt = (1 − t)x0 + tx1 and is trained to output the constant velocity of that straight path:

L = 𝔼 ‖ (x1 − x0) − uθ(xt, t) ‖²B.5

2.1  Adding time conditioning

The right update near t = 0 (almost pure noise) is very different from the right update near t = 1, so the network needs to know t. I push the scalar t (shape (N, 1), already in [0, 1]) through an FCBlock (Linear → GELU → Linear) and use the result to multiply two feature maps: the unflatten output by t1 (2D channels) and the first up-block output by t2 (D channels). The rest of the UNet is unchanged.

unflatten ← unflatten ⊙ t1,   up1 ← up1 ⊙ t2
show code · FCBlock, time-conditioned UNet, training loss (Alg. B.1) and sampler (Alg. B.2)
class FCBlock(nn.Module):               # Linear -> GELU -> Linear
    def __init__(self, in_channels, out_channels):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(in_channels, out_channels), nn.GELU(),
                                 nn.Linear(out_channels, out_channels))
    def forward(self, x): return self.net(x)

class TimeConditionalUNet(_UNetBody):
    def __init__(self, in_channels, num_classes, num_hiddens):
        super().__init__(in_channels, num_hiddens)
        D = num_hiddens
        self.fc1_t = FCBlock(1, 2 * D)  # matches the unflatten block's 2D channels
        self.fc2_t = FCBlock(1, D)      # matches the first up block's D channels

    def forward(self, x, t):
        t = t.reshape(-1, 1).to(x.dtype)
        t1 = _as_channels(self.fc1_t(t))                 # (N, 2D, 1, 1)
        t2 = _as_channels(self.fc2_t(t))                 # (N, D, 1, 1)
        return self._forward(x, lambda h: h * t1, lambda h: h * t2)

def time_fm_forward(unet, x_1, num_ts):                  # Algorithm B.1
    x_0 = torch.randn_like(x_1)
    t = torch.rand(x_1.shape[0], device=x_1.device)
    x_t = (1 - t.reshape(-1,1,1,1)) * x_0 + t.reshape(-1,1,1,1) * x_1
    return F.mse_loss(unet(x_t, t), x_1 - x_0)           # target: the straight-line velocity

@torch.inference_mode()
def time_fm_sample(unet, img_wh, num_ts, seed=0, num_samples=40):   # Algorithm B.2
    gen = torch.Generator(device=device).manual_seed(seed)
    x = torch.randn((num_samples, 1, *img_wh), generator=gen, device=device)
    dt = 1.0 / num_ts
    for i in range(num_ts):
        t = torch.full((num_samples,), i * dt, device=device)
        x = x + dt * unet(x, t)                           # Euler step
    return x

2.2  Training the time-conditioned UNet

D = 64 · batch 64 · Adam, lr 1e-2 · ExponentialLR, γ = 0.11/10, stepped once per epoch · 10 epochs

The scheduler takes the learning rate from 1e-2 down to about 1e-3 over the run. The loss sits way higher than in Part 1 (it ends around 0.09) and then flattens instead of heading to zero. That’s expected: the target x1 − x0 contains a full unit-variance noise image that the network can only partly predict from xt, especially near t = 0, where xt is almost pure noise and the digit part of the target is basically a guess.

2.3  Sampling from the time-conditioned UNet

Start from x0 ∼ 𝒩(0, I) and take 50 Euler steps of size 1/50 along the predicted velocity. I used the same starting noise (seed 0, 40 samples) at every checkpoint, so any difference between the grids comes only from training.

At epoch 1, the samples are mostly stroke-like squiggles with a few recognizable digits. By epoch 5, most are digit-shaped, and by epoch 10, more of them are legible, but plenty are still malformed or somewhere between two classes. That’s the limit of time-only conditioning: the model has to commit to a digit purely from where the noise happens to sit, and with 50 Euler steps and a small UNet, some trajectories end up between modes.

2.4  Adding class conditioning

To get better samples and control over which digit comes out, I condition on the class too. The label becomes a one-hot vector of length 10 and goes through two more FCBlocks. This time the class acts as a per-channel gain and time as a per-channel bias:

unflatten = c1 ⊙ unflatten + t1,   up1 = c2 ⊙ up1 + t2

10% of the time (puncond = 0.1) the one-hot vector is zeroed out during training, so the same network also learns the unconditional flow. That’s what makes classifier-free guidance possible at sampling time.

show code · class-conditioned UNet, training loss (Alg. B.3) and CFG sampler (Alg. B.4)
class ClassConditionalUNet(_UNetBody):
    def __init__(self, in_channels, num_classes, num_hiddens):
        super().__init__(in_channels, num_hiddens)
        D = num_hiddens
        self.num_classes = num_classes
        self.fc1_t, self.fc1_c = FCBlock(1, 2 * D), FCBlock(num_classes, 2 * D)
        self.fc2_t, self.fc2_c = FCBlock(1, D),     FCBlock(num_classes, D)

    def forward(self, x, c, t, mask=None):
        c_vec = F.one_hot(c.long(), self.num_classes).to(x.dtype)       # (N, 10)
        if mask is not None:
            c_vec = c_vec * mask.reshape(-1, 1).to(x.dtype)             # mask 0 -> all-zero "null" class
        t = t.reshape(-1, 1).to(x.dtype)
        t1, c1 = _as_channels(self.fc1_t(t)), _as_channels(self.fc1_c(c_vec))
        t2, c2 = _as_channels(self.fc2_t(t)), _as_channels(self.fc2_c(c_vec))
        # class is a per-channel gain, time is a per-channel bias
        return self._forward(x, lambda h: c1 * h + t1, lambda h: c2 * h + t2)

def class_fm_forward(unet, x_1, c, p_uncond, num_ts):                    # Algorithm B.3
    n = x_1.shape[0]
    x_0 = torch.randn_like(x_1)
    t = torch.rand(n, device=x_1.device)
    x_t = (1 - t.reshape(-1,1,1,1)) * x_0 + t.reshape(-1,1,1,1) * x_1
    mask = (torch.rand(n, device=x_1.device) >= p_uncond).float()       # drop the class 10% of the time
    return F.mse_loss(unet(x_t, c, t, mask), x_1 - x_0)

@torch.inference_mode()
def class_fm_sample(unet, c, img_wh, num_ts, guidance_scale=5.0, seed=0):   # Algorithm B.4
    n = c.shape[0]
    gen = torch.Generator(device=device).manual_seed(seed)
    x = torch.randn((n, 1, *img_wh), generator=gen, device=device)
    c2 = torch.cat([c, c])
    mask2 = torch.cat([torch.ones(n, device=device), torch.zeros(n, device=device)])
    dt = 1.0 / num_ts
    for i in range(num_ts):
        t = torch.full((2 * n,), i * dt, device=device)
        u = unet(torch.cat([x, x]), c2, t, mask2)                        # cond + uncond in one batch
        u_cond, u_uncond = u.chunk(2)
        x = x + dt * (u_uncond + guidance_scale * (u_cond - u_uncond))
    return x

2.6  Sampling with classifier-free guidance

Now 300 Euler steps, guidance γ = 5, and four instances of each digit (each column is one digit, each row a new instance). Same seed at every checkpoint.

u = uuncond + γ (ucond − uuncond),  γ = 5B.6

Class conditioning helps a lot. Even at epoch 1, most columns are the right digit (0, 1, 2, 3 and 7 are already good), though the 4, 5, 6, 8 and 9 columns are still shaky or broken. By epoch 5, they’re mostly clean, and by epoch 10, every sample is a well-formed, correctly labeled digit, with different slants and thicknesses down each column. Compared with the time-only model, the network no longer has to decide what to draw from the noise alone: the class (pushed harder by γ = 5) picks the mode, and the flow only has to fill in the style.

Getting rid of the learning-rate scheduler

What I changed: I removed the scheduler and used a constant learning rate of 1e-3 instead of starting at 1e-2, with everything else identical (same seed, epochs, batch size, puncond and sampler).

Why that’s enough: The exponential schedule slides the rate from 1e-2 to about 1e-3, so the quality of the final samples is mostly decided by the late epochs, which already run at roughly 1e-3. Adam’s step size is about the learning rate no matter how big the gradient is, so 1e-2 makes fast but jumpy progress early on and the decay is what lets the weights settle at the end. If I start at the “settled” rate, I get that stable ending for free.

Part B, in one paragraph

A one-shot denoiser works when the input still carries information about the digit and falls apart the moment it doesn’t: the pure-noise model collapsed onto the dataset mean, which is what MSE says it should do. Flow matching sidesteps that by never asking the network to do the whole job at once. It learns a velocity field and takes many small steps, so each one only has to resolve a little uncertainty, and adding the class (with 10% dropout so CFG works) turned a sampler that sometimes lands between digits into one that reliably draws the digit you ask for. The scheduler experiment was a good reminder that the early-training behavior and the final result can disagree: the constant rate looked better for the first few epochs and the scheduled run still won in the end.

§Takeaways

Across both parts, it was satisfying to see the same few ideas show up at completely different scales. The straight-line path (1 − t) ε + t x and the CFG extrapolation are identical in A and B; one is 7.89M parameters on 28×28 digits and the other is a huge pretrained model on 512×512 pixels, and both get their quality from small steps and guidance.
