A.2 Recovering homographies

A homography sends a point (x, y) in one image to (x′, y′) in another through a 3×3 matrix, followed by a division by the third coordinate. Scaling H doesn't change the mapping, so I fix H33 = 1 and that leaves 8 unknowns.

Four points would pin H down exactly, but then a couple of pixels of click error swing it a lot. So I clicked 8 points per pair (6 for mosaic 2's right-to-centre pair), stacked all the rows into one tall A h = b with A of size 2n × 8, and let np.linalg.lstsq find the h that minimises ‖A h − b‖². build_system makes A and b, and computeH(im1_pts, im2_pts) solves it.

code: build_system, computeH 
def build_system(im1_pts, im2_pts):
    """Stack A h = b for the 8 unknowns of H (H[2,2] = 1). Two rows per point."""
    A, b = [], []
    for (x, y), (xp, yp) in zip(im1_pts, im2_pts):
        A.append([x, y, 1, 0, 0, 0, -x * xp, -y * xp]); b.append(xp)
        A.append([0, 0, 0, x, y, 1, -x * yp, -y * yp]); b.append(yp)
    return np.array(A, float), np.array(b, float)


def computeH(im1_pts, im2_pts):
    """Least-squares homography with im2_pts ~ H @ im1_pts (both n x 2, (x, y))."""
    A, b = build_system(im1_pts, im2_pts)
    h = np.linalg.lstsq(A, b, rcond=None)[0]
    return np.append(h, 1).reshape(3, 3)

A.3 Warping the images, and rectification

warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H) both use inverse warping. I push the four corners of the image through H to get the bounding box of the output. Then every output pixel goes back through H−1 to find where it should read from in the source. Doing it this way means every output pixel gets asked for a value, so there are no holes. Output pixels whose source lands outside the photo get mask = 0, which matters later for blending.

Iout(x, y) = Isrc( H−1 [x, y, 1]T )

The two methods differ only in how they read the source at a non-integer position. nearest neighbour rounds to the closest pixel and copies it. bilinear takes a weighted average of the four pixels around the position, using the fractional parts a = x − ⌊x⌋ and b = y − ⌊y⌋ as weights:

I(x, y) = (1−a)(1−b) I00 + a(1−b) I10 + (1−a) b I01 + a b I11
code: output_bbox, inverse_coords, warpImageNearestNeighbor, warpImageBilinear 
def apply_H(H, pts):
    p = np.c_[pts, np.ones(len(pts))] @ H.T
    return p[:, :2] / p[:, 2:3]


def output_bbox(shape, H):
    """Integer bounding box (xmin, ymin, xmax, ymax) of the image's corners pushed through H."""
    h, w = shape[:2]
    c = apply_H(H, np.array([[0, 0], [w - 1, 0], [w - 1, h - 1], [0, h - 1]], float))
    return (int(np.floor(c[:, 0].min())), int(np.floor(c[:, 1].min())),
            int(np.ceil(c[:, 0].max())), int(np.ceil(c[:, 1].max())))


def inverse_coords(H, bbox):
    """For every output pixel in bbox, the (x, y) it reads from in the source (via H^-1)."""
    xmin, ymin, xmax, ymax = bbox
    xs, ys = np.meshgrid(np.arange(xmin, xmax + 1), np.arange(ymin, ymax + 1))
    p = np.stack([xs.ravel(), ys.ravel(), np.ones(xs.size)]) 
    q = np.linalg.inv(H) @ p
    return (q[0] / q[2]).reshape(xs.shape), (q[1] / q[2]).reshape(xs.shape)


def warpImageNearestNeighbor(im, H, bbox=None):
    h, w = im.shape[:2]
    bbox = bbox or output_bbox(im.shape, H)
    sx, sy = inverse_coords(H, bbox)
    col, row = np.round(sx).astype(int), np.round(sy).astype(int)
    mask = (col >= 0) & (col < w) & (row >= 0) & (row < h)
    out = np.zeros(sx.shape + im.shape[2:], dtype=float)
    out[mask] = im[row[mask], col[mask]]
    return out, mask.astype(float), bbox


def warpImageBilinear(im, H, bbox=None):
    h, w = im.shape[:2]
    bbox = bbox or output_bbox(im.shape, H)
    sx, sy = inverse_coords(H, bbox)
    mask = (sx >= 0) & (sx <= w - 1) & (sy >= 0) & (sy <= h - 1)
    x, y = sx[mask], sy[mask]
    x0 = np.minimum(np.floor(x).astype(int), w - 2)   # top-left neighbour
    y0 = np.minimum(np.floor(y).astype(int), h - 2)
    a, b = x - x0, y - y0                              # fractional parts
    if im.ndim == 3:
        a, b = a[:, None], b[:, None]
    out = np.zeros(sx.shape + im.shape[2:], dtype=float)
    out[mask] = ((1 - a) * (1 - b) * im[y0, x0] + a * (1 - b) * im[y0, x0 + 1]
                 + (1 - a) * b * im[y0 + 1, x0] + a * b * im[y0 + 1, x0 + 1])
    return out, mask.astype(float), bbox

A.4 Blending into mosaics

The reference image stays unwarped. The other two are warped into its frame with bilinear interpolation onto one shared canvas, which is the union of all three bounding boxes. That gives a stack of aligned images plus a mask for each, and the only question left is how to combine them. I tried three ways:

overwrite Later images simply paste over earlier ones. It's the baseline.

feathering A weighted average, where an image's weight at a pixel is its distance to the nearest empty pixel, so it's biggest in the middle of an image and fades to 0 at its border.

two-band Split each image into low and high frequencies. The low frequencies, which carry colour and exposure, get the feathered average. The high frequencies, which carry edges and fine detail, come from whichever image has the larger weight at that pixel. Colour blends smoothly across the overlap, but each edge comes from a single image, so it can't ghost.

Ifeather = Σi wi Ii / Σi wi     Itwo-band = Σi wi LP(Ii) / Σi wi + HP(Iargmax w)

HP = I − LP

code: warp_to_canvas, edge_weights, blend_overwrite, blend_feather, blend_laplacian 
# uses: from scipy.ndimage import distance_transform_edt, gaussian_filter

def warp_to_canvas(images, Hs, warp):
    """Warp every image (H maps it into the reference frame) onto one shared canvas."""
    boxes = [output_bbox(im.shape, H) for im, H in zip(images, Hs)]
    bbox = (min(b[0] for b in boxes), min(b[1] for b in boxes),
            max(b[2] for b in boxes), max(b[3] for b in boxes))
    warped, masks = [], []
    for im, H in zip(images, Hs):
        w_, m_, _ = warp(im, H, bbox)
        warped.append(w_); masks.append(m_)
    return warped, masks, bbox


def edge_weights(masks):
    """Weight = distance to the nearest empty pixel: biggest mid-image, 0 at the border."""
    return [distance_transform_edt(m > 0) for m in masks]


def blend_overwrite(warped, masks):
    out = np.zeros_like(warped[0])
    for w_, m in zip(warped, masks):
        out[m > 0] = w_[m > 0]
    return out


def blend_feather(warped, masks):
    ws = edge_weights(masks)
    num = sum(w_ * wt[..., None] for w_, wt in zip(warped, ws))
    den = sum(ws)[..., None]
    return np.where(den > 0, num / np.maximum(den, 1e-8), 0)


def blend_laplacian(warped, masks, sigma=4):
    """Two-band: feather the low frequencies, take the high ones from the heaviest image."""
    ws = edge_weights(masks)
    lows, highs = [], []
    for w_, m in zip(warped, masks):
        lows.append(gaussian_filter(w_, (sigma, sigma, 0)))
        highs.append(w_ - lows[-1])
    den = np.maximum(sum(ws), 1e-8)[..., None]
    low = sum(l * wt[..., None] for l, wt in zip(lows, ws)) / den
    best = np.argmax(np.stack(ws), axis=0)                        # which image wins here
    high = np.take_along_axis(np.stack(highs), best[None, ..., None], axis=0)[0]
    covered = (sum(masks) > 0)[..., None]
    return np.clip(low + high, 0, 1) * covered

Part B

B.1 Harris corners and ANMS

For a pair of photos, Part B finds corners in each, describes the patch around every corner, matches descriptors across the two photos, and runs RANSAC to discard the wrong matches before solving for H. The warping and blending are Part A's code, unchanged (mosaic.py). Everything new is in autostitch.py. The photos, the reference frames and my Part A clicks all come from the same config.json, so the manual and automatic mosaics at the end are built from identical inputs.

500 corners per image · 8×8 descriptor from a 40×40 window · ratio < 0.6 · RANSAC 5000 iterations, ε = 3 px

For corners I used the provided harris.py: single scale, σ = 1, and anything within 20 px of the border is dropped so a 40×40 window always fits. It returns every local maximum of the Harris response, which is a lot of points: 16,626 in the mosaic 1 image below and about 17,000 in each of the other two. I discard anything weaker than 0.5% of the strongest response, and I still have to pick 500.

The obvious pick is the 500 strongest, but those clump (middle panels). So I use adaptive non-maximal suppression. Each corner gets a suppression radius: the distance to the nearest corner that is clearly stronger than it.

ri = minj ‖xi − xj‖    such that    f(xi) < c · f(xj),    c = 0.9

The strongest corner in the image has no stronger neighbour, so its radius is infinite and it always survives. I keep the 500 corners with the largest radii, which gives points that are strong and also have some room around them.

Comparing every corner with every other one is slow. After sorting by strength, the corners that count as clearly stronger than corner i are just a prefix of the sorted list, so each block of 1,024 corners only gets compared against the ones before it.

code: detect_features, anms 
def detect_features(im, n_keep=500, rel_thresh=0.005, max_candidates=20000, c_robust=0.9,
                    select="anms", blur_sigma=None, seed=0):
    gray = color.rgb2gray(im)
    pts, S = harris_candidates(gray)
    all_pts = pts
    keep = S >= rel_thresh * S.max()
    pts, S = pts[keep], S[keep]
    if len(S) > max_candidates:     # safety cap for pathological images
        top = np.argsort(-S)[:max_candidates]
        pts, S = pts[top], S[top]

    if select == "anms":
        order, _ = anms(pts, S, n_keep, c_robust)
    elif select == "strength":
        order = np.argsort(-S, kind="stable")[:n_keep]
    elif select == "random":
        order = np.random.default_rng(seed).permutation(len(S))[:n_keep]
    else:
        raise ValueError(select)

    desc = extract_descriptors(gray, pts[order], blur_sigma=blur_sigma)
    return Features(pts[order], desc, S[order], all_pts, gray)


def anms(pts, strength, n_keep=500, c_robust=0.9, chunk=1024):
    order = np.argsort(-strength, kind="stable")
    p, st = pts[order], strength[order]
    n_stronger = np.searchsorted(-c_robust * st, -st, side="left")    # size of prefix per point
    r2 = np.full(len(p), np.inf)
    for s in range(0, len(p), chunk):
        idx = np.arange(s, min(s + chunk, len(p)))
        k = n_stronger[idx].max()
        if k == 0:
            continue
        d2 = dist2(p[idx], p[:k])
        d2[np.arange(k)[None, :] >= n_stronger[idx][:, None]] = np.inf
        r2[idx] = d2.min(axis=1)
    radii = np.empty(len(p))
    radii[order] = np.sqrt(np.maximum(r2, 0))
    return np.argsort(-radii, kind="stable")[:n_keep], radii

Without ANMS, the strongest 500 pile up on a few high-contrast spots: the tree on the left in mosaic 1, and the window frames and arches in mosaics 2 and 3. After ANMS, the same 500 points also land on the stairs, the plain wall and the paving. However, paving and stair bricks are repetitive, so those points could be easy to confuse with their neighbours.

B.2 Feature descriptors

Each corner is described by the 40×40 patch of grayscale around it, but not by all 1,600 pixels. I blur the image with a Gaussian (σ = 2.5), then sample the blurred image on an 8×8 grid with 5 px spacing, so each of the 64 samples roughly summarises its own 5×5 cell. Sampling from the blurred image is what makes the descriptor big and smooth, so a match survives a corner being a pixel or two off. Finally I bias/gain normalise, so a brighter or flatter exposure of the same spot gives the same 64 numbers.

d = (d − μd) / σd

The patches are axis-aligned, with no rotation invariance. My photos are all upright and panned sideways, so features shouldn't rotate much between neighbours.

code: extract_descriptors 
def extract_descriptors(gray, pts, window=40, size=8, blur_sigma=None):
    spacing = window / size
    blur_sigma = spacing / 2 if blur_sigma is None else blur_sigma   # each sample ~ its 5x5 cell
    blurred = ndimage.gaussian_filter(gray, blur_sigma)
    offs = (np.arange(size) - (size - 1) / 2.0) * spacing            # centred on the point
    oy, ox = np.meshgrid(offs, offs, indexing="ij")
    cy = pts[:, 1, None, None] + oy[None]
    cx = pts[:, 0, None, None] + ox[None]
    patches = ndimage.map_coordinates(blurred, np.stack([cy, cx]), order=1, mode="nearest")
    d = patches.reshape(len(pts), -1)
    return (d - d.mean(axis=1, keepdims=True)) / (d.std(axis=1, keepdims=True) + 1e-8)

Features 1, 5 and 6 (a wall corner, and the balcony railing) turn into clean light/dark splits. Feature 3 is the “N” in the building's sign. The window shows the letter clearly, but the descriptor is a smooth ramp with no trace of it. That's what the blur is for.

B.3 Matching with the ratio test

For every descriptor in image 1, I find its nearest and second-nearest descriptor in image 2 (squared distances from dist2 in harris.py, then square-rooted). I only keep the match if the nearest one is a lot closer than the runner-up, which is Lowe's ratio test:

e1-NN / e2-NN < 0.6
code: nearest_neighbours, match_features 
def nearest_neighbours(d1, d2):
    D = np.maximum(dist2(d1, d2), 0)
    two = np.argsort(D, axis=1)[:, :2]
    rows = np.arange(len(d1))
    d_1, d_2 = np.sqrt(D[rows, two[:, 0]]), np.sqrt(D[rows, two[:, 1]])
    mutual = D.argmin(axis=0)[two[:, 0]] == rows
    return two[:, 0], d_1 / (d_2 + 1e-12), mutual


def match_features(d1, d2, ratio_thresh=0.6, cross_check=False):
    nn, ratio, mutual = nearest_neighbours(d1, d2)
    keep = (ratio < ratio_thresh) & (mutual if cross_check else True)
    idx1 = np.flatnonzero(keep)
    return idx1, nn[idx1], ratio[idx1]

Choosing the threshold

To pick 0.6, I ran RANSAC first (next section) and used its H to label every feature in image 0: is its nearest neighbour in image 1 where H says it should be? Of the 500 features, 184 are and 316 aren't.

The consistent features (teal) mostly have ratios between 0.3 and 0.6. The inconsistent ones (red) pile up against 1, because for them there's nothing good to find. That's a lot of red, but image 0 only overlaps image 1 partly, so I'd expect many of its features to have no partner. The threshold of 0.6 sits about where the two piles stop overlapping much. It isn't a clean cut: a thin tail of consistent features runs past 0.6 and I lose those, and a few inconsistent ones sneak in below it.

Most lines run roughly parallel. A few cross the image at steep angles, mostly in the upper left, and those are wrong. They passed the ratio test because their descriptors happen to look alike, so these matches can't go straight into least squares.

B.4 RANSAC and automatic mosaics

Least squares over all 119 matches would let the wrong ones drag H around. 4-point RANSAC, written from scratch, avoids that:

  1. Pick 4 matches at random. If any three of them are nearly collinear in either image, skip the sample, since four points like that don't pin down a homography.
  2. Solve for H exactly from those 4 with Part A's computeH.
  3. Count the matches whose projected position H p1 lands within ε = 3 px of p2. Those are the inliers.
  4. Repeat 5000 times and keep the largest inlier set (ties go to the smaller total error). Then refit H by least squares on all of its inliers, recompute the inliers once with the refit H, and refit again.

One change to computeH: it now takes normalize=True, which shifts the points so their centroid is the origin, scales them so the average distance from it is √2, solves, then undoes that.

code: computeH with normalisation, ransac_homography, auto_homographies 
def _normalizer(p):
    c = p.mean(axis=0)
    s = np.sqrt(2) / (np.linalg.norm(p - c, axis=1).mean() + 1e-12)
    return np.array([[s, 0, -s * c[0]], [0, s, -s * c[1]], [0, 0, 1.0]])


def computeH(im1_pts, im2_pts, normalize=False):
    p = np.asarray(im1_pts, dtype=np.float64)
    q = np.asarray(im2_pts, dtype=np.float64)
    if len(p) < 4:
        raise ValueError("need at least 4 correspondences")
    if normalize:
        T1, T2 = _normalizer(p), _normalizer(q)
        p, q = apply_homography(T1, p), apply_homography(T2, q)
    h, *_ = np.linalg.lstsq(*build_system(p, q), rcond=None)
    H = np.append(h, 1.0).reshape(3, 3)
    if normalize:
        H = np.linalg.inv(T2) @ H @ T1
        H = H / H[2, 2]
    return H


def _degenerate(p, min_area2=1.0):
    for a, b, c in ((0, 1, 2), (0, 1, 3), (0, 2, 3), (1, 2, 3)):
        v1, v2 = p[b] - p[a], p[c] - p[a]
        if abs(v1[0] * v2[1] - v1[1] * v2[0]) < min_area2:
            return True
    return False


def ransac_homography(p1, p2, n_iter=5000, eps=3.0, seed=0):
    rng = np.random.default_rng(seed)
    n = len(p1)
    best, best_err = np.zeros(n, bool), np.inf
    for _ in range(n_iter if n >= 4 else 0):
        idx = rng.choice(n, 4, replace=False)
        if _degenerate(p1[idx]) or _degenerate(p2[idx]):
            continue
        H = M.computeH(p1[idx], p2[idx], normalize=True)
        if not np.all(np.isfinite(H)):
            continue
        err = M.reprojection_error(H, p1, p2)
        inl = err < eps
        if inl.sum() > best.sum() or (inl.sum() == best.sum() and inl.any() and err[inl].sum() < best_err):
            best, best_err = inl, err[inl].sum()
    if best.sum() < 4:
        return None, best
    H = M.computeH(p1[best], p2[best], normalize=True)             # least-squares refit
    inliers = M.reprojection_error(H, p1, p2) < eps
    if inliers.sum() >= 4:
        H = M.computeH(p1[inliers], p2[inliers], normalize=True)
    return H, inliers


def auto_homographies(images, ref=None, feats=None, n_keep=500, ratio_thresh=0.6, eps=3.0,
                      n_iter=5000, seed=0):
    ref = len(images) // 2 if ref is None else ref
    feats = feats or [detect_features(im, n_keep=n_keep) for im in images]
    pairs = [match_pair(feats[i], feats[i + 1], ratio_thresh, False, n_iter, eps, seed)
             for i in range(len(images) - 1)]
    for i, p in enumerate(pairs):
        if p["H"] is None or p["inliers"].sum() < 8:
            raise RuntimeError(f"pair {i}->{i + 1}: only {p['inliers'].sum()} inliers; "
                               "loosen ratio_thresh or check the overlap")
    Hs = M.chain_homographies(len(images), ref, [(i, i + 1, p["H"]) for i, p in enumerate(pairs)])
    return Hs, dict(feats=feats, pairs=pairs, ref=ref)

auto_homographies does this for each neighbouring pair, then chains the results into the middle image's frame with Part A's chain_homographies.

What I learned

The biggest surprise was how much of this project came down to the photos, not the code. Once the solve and the warps worked, the rectifications came out clean on the first try. The mosaics were different. Every misalignment I saw (the glass door reflections, the railing, the ground close to the camera) was something that doesn't sit on the same plane as the wall. A homography can only line up one plane, or a scene seen from a single spot.

Part B changed how I read Part A's numbers. In Part A, I treated the reprojection error on my clicked points as a measure of how good each H was. Now, the automatic H disagrees with my clicks by 2 to 5.6 px and the mosaics still look the same, so that number was mostly telling me how well H fit my own clicks, which have error of their own.
